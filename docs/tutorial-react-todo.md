# Tutorial: A React to-do app on Saltcorn v2

This walks from a freshly bootstrapped server (first admin user already created) to a working React
to-do app that reads and writes its data through Saltcorn's generated API client.

## Prerequisites: how you start the server

An application is served on **its own subdomain**, and its React source is built from a **file
store** on the server's disk. So start `saltcorn serve` with both wired up:

```bash
saltcorn serve \
  --file-store apps=/srv/apps \
  --base-domain localhost
```

- `--file-store apps=/srv/apps` connects a store named `apps` backed by that directory. Your app's
  source will live under it. The design expects source stores to be git repos, so `git init` inside
  your app folder.
- `--base-domain localhost` turns on subdomain routing, so an app with subdomain `todo` is reachable
  at `http://todo.localhost:3000` (browsers resolve `*.localhost` to 127.0.0.1). Without a base
  domain, only the admin UI is served.

You've already created the first user, so sign in to the admin UI at `http://localhost:3000`.

## Step 1 — Build the data model

In the admin UI, go to **Tables**:

1. **Create a table** named `tasks`. New tables get an auto `id` primary key
   (`bigint generated by default as identity`), so rows are addressable — that's what makes
   update/delete work.
2. Open the table and **add fields**:
   - `title` — SQL type `text`, not nullable
   - `done` — SQL type `boolean`, not nullable

That's the whole schema. A table's read/write access roles govern who may call its API (below).

## Step 2 — Scaffold the React app in the file store

On the server host, create a standard Vite React app inside the `apps` store directory:

```bash
cd /srv/apps
npm create vite@latest todo -- --template react-ts
cd todo && npm install && git init
```

You now have `/srv/apps/todo`, building to `/srv/apps/todo/dist`.

## Step 3 — Register the application

In the admin UI, go to **Applications → New application** and fill in:

| Field | Value |
|---|---|
| Name | `Todo` |
| Subdomain | `todo` |
| Framework | `code` |
| **File store** | `apps` |
| **Source directory** | `todo` |
| **Output directory** | `todo/dist` |
| **Build command** | `npm run build` |
| **Generated client path** | `todo/src/client.ts` |
| Tables | `tasks` |
| APIs (Provider / Mount) | `rest` / `/api` |

The paths are all relative to the file store. `rest` at `/api` projects each declared table into
four endpoints — `GET/POST /api/tasks` and `PUT/DELETE /api/tasks/{id}` — plus `/api/login`,
`/api/logout`, `/api/whoami`. Save.

## Step 4 — Build the application

On the app's row, click **Build**. The server:

1. emits a typed TypeScript client to `todo/src/client.ts` (generated from *this app's* endpoints),
   then
2. runs `npm run build` in the store, and
3. serves the resulting `todo/dist` bundle (SPA fallback to `index.html`).

The build banner shows the bundler's log, or its diagnostics if it fails.

## Step 5 — Use the generated client in React

The generated `client.ts` gives you a typed factory. Endpoint paths already include the `/api`
mount, so no base URL is needed:

```tsx
// src/App.tsx
import { useEffect, useState } from "react";
import { createClient } from "./client";

const api = createClient();

export default function App() {
  const [tasks, setTasks] = useState<any[]>([]);
  const [title, setTitle] = useState("");

  const refresh = async () => setTasks(await api.listTasks());
  useEffect(() => { refresh(); }, []);

  const add = async () => {
    await api.createTasks({ title, done: false });
    setTitle("");
    refresh();
  };

  const toggle = async (t: any) => {
    await api.updateTasks(t.id, { title: t.title, done: !t.done });
    refresh();
  };

  return (
    <div>
      <input value={title} onChange={(e) => setTitle(e.target.value)} />
      <button onClick={add}>Add</button>
      <ul>
        {tasks.map((t) => (
          <li key={t.id}>
            <input type="checkbox" checked={t.done} onChange={() => toggle(t)} />
            {t.title}
            <button onClick={() => api.deleteTasks(t.id).then(refresh)}>✕</button>
          </li>
        ))}
      </ul>
    </div>
  );
}
```

Method names come from the table: `listTasks`, `createTasks`, `updateTasks(id, …)`,
`deleteTasks(id)`. If the `tasks` table's access requires a logged-in role, authenticate first with
`await api.login({ … })` (it sets a session cookie); `api.whoami()` returns the current user.

## Step 6 — Open the app

Rebuild after code changes (**Build** again — no server restart needed), then visit:

```
http://todo.localhost:3000
```

You've got a React front end whose only path to data is the typed, access-controlled API Saltcorn
generated from your table.

## Two things that trip people up

- **Reachability** is entirely on `--base-domain`; without it you'll only ever see the admin UI, not
  the app.
- **API access** follows each table's read/write roles — if the to-do list comes back empty or 401s,
  check the `tasks` table's access or add a `login` call.
